# 柚柚今天吃什么

一个**纯静态、免后端、离线可用**的"今天吃什么 + 一周食谱"小应用。手机浏览器打开一次，装到主屏幕就像 App 一样用，菜谱数据存在你自己手机里。

---

## 它能干什么

| 功能 | 说明 |
| --- | --- |
| **导入菜单** | 支持三种方式：① 手动一条条新增；② 一次性粘贴文本批量导入；③ 选择 `.txt / .csv / .json` 文件导入 |
| **菜谱拆解** | 每道菜拆成"食材 + 用量"，食材再关联到营养功能。导入"番茄炒鸡蛋 + 番茄/鸡蛋"后，生成菜单时菜名下面就会列出番茄和鸡蛋各自的营养功能 |
| **备料 + 做法** | 打开任一道菜，**第一屏就是「备料清单（带用量）+ 分步做法」**，站在灶台前不用翻。菜谱页和今日/本周的每道菜后面都有「做法 N 步」标记，一眼知道点进去有什么 |
| **随机一周食谱** | 早/中/晚三餐，按"主食 + 荤 + 素（+汤）"配比自动搭配。**优先保证不重复**：同一餐内不重复、同一天跨餐不重复、一周内尽量摊开、并避开最近半个月吃过的 |
| **锁与换** | 每餐可单独"换一换"、可"锁定"（重新生成时不被覆盖）、可手动加菜 |
| **每日金句** | 每天按日期固定展示一条，可自己添加，加满 100 条就是 100 天不重样 |
| **采购清单** | 按一周食谱自动聚合食材、合并计数、按品类排序，可勾选、可一键复制 |
| **数据本地化** | 全部数据存浏览器 `localStorage`，不联网不上传；支持导出/恢复 `.json` 备份 |

内置了 **40 道家常菜、77 种食材的营养功能说明、50 条金句** 作为起步数据，第一次打开就能直接生成一周食谱。

### 内置数据是照着「3 岁幼儿能吃什么」筛过的

这不是一个通用菜谱库，是按"家里有个 3 岁小孩"的尺度挑过的，选食材/写做法时遵循这几条：

| 原则 | 具体做法 |
| --- | --- |
| **避开窒息风险食物** | 整粒坚果、整颗葡萄/草莓/冬枣、整朵木耳是幼儿最典型的窒息原因。这些食材保留（大人也吃），但提示与菜谱里都写明了处理方式：核桃花生必须碾碎或做酱、葡萄纵向切半去籽、枣去核切瓣、草莓切 4 瓣、木耳切细丝 |
| **不出现咖啡因与酒精** | 删掉了「可乐鸡翅」（可乐含咖啡因与大量游离糖），全库调料里没有料酒、黄酒 |
| **不出现加工/高钠食材** | 删掉了「皮蛋瘦肉粥」（加工蛋、钠高，且原数据把皮蛋错记成鸡蛋） |
| **不出现辛辣刺激** | 全库没有花椒、辣椒、豆瓣酱；「麻婆豆腐」保留但改成了不放豆瓣酱与花椒的不辣家常版 |
| **避开粗纤维难咀嚼** | 删掉了「韭菜」和「韭菜炒鸡蛋」（粗纤维、幼儿咀嚼吞咽困难且易胀气），换成「菠菜炒鸡蛋」 |
| **必须做熟** | 三文鱼、鳕鱼、牛排、鸭血、鸡蛋的提示里都写明了"幼儿务必全熟"；没有刺身类做法 |
| **去骨去刺** | 排骨、牛尾骨、鸡翅、鲈鱼、鳕鱼的提示与菜谱说明里都要求给幼儿前剔净碎骨、摸一遍鱼刺 |

新增的基础荤菜（牛肉、牛里脊、牛排、牛尾骨、排骨、鸡肉、鳕鱼、鸭血）都配了对应的幼儿友好菜谱，比如番茄牛肉滑蛋（番茄的维生素C提高牛肉铁的吸收）、清蒸鳕鱼、鸭血豆腐汤（补铁）、白萝卜炖牛尾、鲜奶蒸蛋羹。

> **关于「豆腐」的命名**：食材库里「北豆腐」与「嫩豆腐」是**两条独立数据**，不是写错。
> 「北豆腐」= 老豆腐 / 卤水豆腐，质地紧实（约 116 kcal、蛋白质 12.2g / 100g），适合红烧、炖汤；
> 「嫩豆腐」= 南豆腐 / 石膏豆腐 / 内酯豆腐，水分高（约 57 kcal、蛋白质 6.2g / 100g），适合麻婆豆腐、豆腐羹。
> 两者热量与蛋白质密度差近一倍，混成一条会让菜谱的营养展示偏高，所以分开维护。
> 日常口语里的「豆腐」默认匹配到北豆腐。

> **关于分类**：豆腐、豆浆归「豆制品」，牛奶、酸奶单独归「饮品」。
> 「纯牛奶（盒装）」是超高温灭菌常温奶，「鲜牛奶」是巴氏冷藏奶，两条独立数据，保质期与储存要求不同。

### 菜谱详情页为什么这么排序

打开一道菜看到的顺序是 **备料 → 做法 → 小贴士 → 调料 → 食材营养功能**，不是随手排的：

最早的做法是把"食材拆解与营养功能"放在最前面，结果每味食材带 3 条功能说明，3 味食材就占掉 670px，
把**做法挤到了 1020px 处**（手机视口只有 681px）——等于打开菜谱根本看不到怎么做。

营养功能是这个应用的特色，但它属于**参考信息**，不该挡在"要做菜"这件事前面。
所以现在第一屏固定给「备料（带用量）+ 分步做法」，营养功能挪到后面。

**做法在数据里存成一个字符串**（`steps`），导入导出、CSV、JSON 备份全都按字符串走，格式没变。
渲染时才由 `js/app.js` 的 `parseSteps()` 拆成步骤数组，能吃下这几种写法：

| 写法 | 解析结果 |
| --- | --- |
| `1. 甲\n2. 乙\n3. 丙` | 三步 |
| `1. 甲 2. 乙 3. 丙`（全挤一行） | 三步 |
| `洗净\n切块\n下锅`（没编号） | 三步行 |
| `1. 甲\n继续说明甲\n2. 乙` | 两步，第二行并进第一步 |

> 行内切分要求编号后有空格，就是为了不把 `0.5 厘米` 这种小数切开。

### 内置数据怎么增量升级（维护须知）

已经打开过 App 的设备，数据存在本地，**不会**因为你改了 `js/data.js` 就自动更新。为此留了版本机制：

- `js/data.js` 末尾的 `window.SEED_REV`：改动内置数据后手动 +1
- `window.SEED_MIGRATIONS`：在数组里追加一条对应 rev 的规则，支持这几种动作：

| 字段 | 作用 |
| --- | --- |
| `patchIngredients` | 按 name 做字段级修改（别名、分类、提示）。**不能改 name**，会断掉菜谱引用 |
| `patchRecipes` | 同上；给 `ingredients` 会顺带重建食材关联 |
| `removeRecipes` | 删除内置菜谱，并自动清理周计划、收藏、使用记录里的引用 |
| `removeIngredients` | 删除内置食材；若仍有菜谱引用会自动跳过，避免把别人的菜谱搞成悬空 |
| `match` + `apply` | 老格式：菜谱食材与旧版逐项一致时整体替换 |
| `onlyIf` | 守卫。写在哪条 patch 上，就只有"当前值仍与旧版一致"时才改 |

- `js/store.js` 的 `applySeedPatch()` 在启动时执行，原则是**不动你改过的东西**：
  1. **补齐**：种子里有、你库里没有的食材和菜谱才加；同名一律跳过（可能是你自己加的）
  2. **迁移**：按 rev 逐级跑上面的规则；`onlyIf` 不满足就整条跳过
- 注意一个已明确的边界：**食材的别名/分类/提示属于内置元数据，会被版本修正覆盖**；
  菜谱的食材与说明则受 `onlyIf` 保护，你自己改过就不会被动。
- 旧备份导入时也会回退版本号并重新体检一次。

## 部署到 GitHub Pages

仓库里已经带了一个自动部署的 workflow（`.github/workflows/deploy.yml`），所以**只需要开一次开关**，之后每次 `git push` 都自动发布。

1. 把文件推到仓库 `main` 分支（根目录）：

   ```
   index.html
   manifest.webmanifest
   sw.js
   icon.svg  icon-192.png  icon-512.png  apple-touch-icon.png
   css/style.css
   js/data.js  js/store.js  js/app.js
   .github/workflows/deploy.yml
   ```

2. 进入仓库 **Settings → Pages**，把 `Source` 改成 **`GitHub Actions`**（不是 `Deploy from a branch`，选错的话 workflow 会报 `Page build type is not 'workflow'`）。

3. 到 **Actions** 标签页，能看到 "部署到 GitHub Pages" 这个 workflow 在跑；跑完（约 30 秒）访问 `https://<你的用户名>.github.io/<仓库名>/`。

> **为什么 Actions 里看不到 workflow？** Pages 有两种部署源，选哪个决定 Actions 里显示什么：
>
> | Source 设置 | Actions 里看到什么 | 需要自己建 workflow 吗 |
> |---|---|---|
> | `GitHub Actions` | 你仓库里的 workflow（本仓库就是「部署到 GitHub Pages」） | **需要**，没有 workflow 就永远不会发布 |
> | `Deploy from a branch` | 只有 GitHub 托管的 `pages-build-deployment` | 不需要 |
>
> 如果选的是 `GitHub Actions` 但仓库里没有 workflow 文件，Pages 就一直不发布，站点是 404，Actions 里空的 —— 这正是"看不到 workflow"最常见的原因。

### 不想用 Actions？

把 `Source` 改回 `Deploy from a branch`、选 `main` + `/ (root)` 就行，那套是 GitHub 自己构建，不需要 workflow 文件。两种方式二选一，不能同时开。

> 想更省事也可以把这个文件夹丢到任意静态托管（Vercel、Netlify、Cloudflare Pages、对象存储），甚至直接双击本地 `index.html` —— 功能完全一样，只有"添加到主屏幕"需要一个 https 网址。

### 装到手机上

- **iPhone / Safari**：打开网址 → 分享按钮 → 「添加到主屏幕」
- **安卓 / Chrome**：打开网址 → 右上角菜单 → 「安装应用」或「添加到主屏幕」

装好之后断网也能打开（`sw.js` 会把页面本身缓存下来）。

## 数据在哪 · 会不会丢

- 菜谱、食材、周计划全部保存在**你这台手机的浏览器本地**（`localStorage`），跟账号无关，也不会上传。
- 因此：**换手机、换浏览器、或清理浏览器数据，数据会丢**。
- 建议：到「我的」页点 **导出备份 (.json)**，把文件存到云盘或发给自己微信。换设备后在同一页点 **从文件恢复** 即可。
- 在微信内置浏览器里打开也能用，但微信可能清理缓存，**强烈建议用系统浏览器打开后添加到主屏幕**。

## 导入格式说明

### 方式一：粘贴文本（推荐，一次可以导入几十道）

```
# 番茄炒鸡蛋
餐次: 午餐, 晚餐
类型: 半荤
标签: 家常, 快手
食材: 番茄 2个; 鸡蛋 3个; 小葱 1根
调料: 食用油; 食盐; 白糖
做法: 1. 鸡蛋打散加一点盐，番茄去皮切块。
2. 热油滑炒鸡蛋至半凝固，盛出备用。
3. 下番茄炒出沙，加少许糖；倒回鸡蛋翻匀，撒葱花出锅。
说明: 番茄要炒到出汁，蛋才嫩。

# 青椒炒豆干
餐次: 午餐, 晚餐
类型: 半荤
食材: 豆干 200g; 青椒 2个; 大蒜 3瓣

@食材 豆干
分类: 豆制品
功能: 提供植物完全蛋白，配谷物可互补氨基酸
功能: 钙含量较高，是很好的植物钙来源
营养: 140 kcal, 蛋白16.2g, 脂肪3.6g, 碳水11.5g, 纤维0.8g
```

规则：

- `# 菜名` 开始一道菜；`@食材 名称` 开始一条食材定义，两者可混写。
- 支持的字段：`餐次`（早/中/晚 或 早餐/午餐/晚餐）、`类型`、`食材`、`调料`、`做法`、`说明`、`标签`；食材定义支持 `分类`、`功能`、`营养`、`贴士`。
- `食材` 用 `;` 或 `,` 分隔，**名称与用量用空格隔开**（`番茄 2个`）；只写名称也可以。
- `做法` 下面可以接着写多行，会自动合并。**建议写成 `1. …` 每步一行**，详情页会渲染成分步骤（编号徽章）；
  不分行也能认，会自动按行或按编号拆开（规则见上面「菜谱详情页为什么这么排序」）。
- `功能` 可以写多行，每行一条；`营养` 写 `140 kcal, 蛋白16.2g, 脂肪3.6g, 碳水11.5g, 纤维0.8g` 这种形式即可被识别。

### 方式二：CSV

表头（中文或英文都行）：

```
菜名,餐次,类型,食材,调料,做法,说明
青椒肉丝,午餐;晚餐,主荤,猪里脊 200g;青椒 2个,食用油;生抽;食盐,切丝快炒,肉要腌一下
```

用 Excel 另存为 CSV 时，编码请选 **UTF-8**，否则中文会乱码（本应用也做了 GBK 兜底，但 UTF-8 最稳）。

### 方式三：JSON 备份

直接导入本应用「导出备份」生成的文件，或在「我的」页用 **从文件恢复** 做整库还原。

## 本地开发

没有构建步骤、没有依赖，改完文件刷新即可。

```bash
# 想带 Service Worker 调试就起个本地服务
cd youyou-eat
python3 -m http.server 8000
# 打开 http://localhost:8000
```

重新生成图标（可选，需要 Pillow）：

```bash
pip install Pillow
python3 tools/make_icons.py
```

## 关于营养数据

内置的营养数值来自常见食物成分表的**近似值**（每 100g 可食部），营养功能描述是通识性的科普表述，**仅供参考，不构成医学或营养建议**。有特殊健康状况（如糖尿病、肾病、甲亢、孕期等）请咨询专业营养师或医生。
